Getting Started

Welcome to the NovaQR official documentation. This guide covers the setup, configuration, database management, and customization of the NovaQR Android application. Our goal is to make everything easy to update and configure.

Prerequisites

  • Supabase Project (for Authentication and Database)
  • Google Cloud Console (for Google Sign-In)
  • Tawk.to Account (for Live Chat Support)

Local Installation & DLSL Build

Follow these steps to compile and install the stable version of NovaQR locally on your Android environment or emulator.

DLSL Build & Compilation Steps

  1. Clone or download the project source code.
  2. Open the project directory in Android Studio (Koala or newer).
  3. Ensure JDK 17+ is configured in Settings > Build, Execution, Deployment > Build Tools > Gradle > Gradle JDK.
  4. Create your .env file in the project root with valid Supabase and API keys.
  5. Run ./gradlew assembleDebug from the terminal or click Run in Android Studio.

Environment Setup (.env)

To make configuration seamless, you can update a wealth of values directly from your .env file. In your project root, locate the .env file (or copy .env.example to .env) and update it with your own values.

# Gemini API Key
GEMINI_API_KEY=YOUR_GEMINI_API_KEY

# Supabase Credentials
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-supabase-anon-key

# Authentication
GOOGLE_LOGIN_KEY=your-google-web-client-id

# Live Chat (Tawk.to)
TAWK_PROPERTY_ID=your-property-id
TAWK_WIDGET_ID=your-widget-id

Database Setup (Supabase)

NovaQR uses Supabase for database storage and row-level security (RLS). You need to create tables for user profiles and saved QRs.

1. Profiles Table

CREATE TABLE IF NOT EXISTS public.profiles (
  id uuid REFERENCES auth.users ON DELETE CASCADE PRIMARY KEY,
  email text,
  full_name text,
  plan text DEFAULT 'free',
  avatar_base64 text,
  created_at timestamp with time zone DEFAULT timezone('utc'::text, now())
);

ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can view own profile" ON public.profiles FOR SELECT USING (auth.uid() = id);
CREATE POLICY "Users can insert own profile" ON public.profiles FOR INSERT WITH CHECK (auth.uid() = id);
CREATE POLICY "Users can update own profile" ON public.profiles FOR UPDATE USING (auth.uid() = id);

2. Saved QRs Table

Execute this SQL to store user-generated QR codes securely:

CREATE TABLE IF NOT EXISTS public.saved_qrs (
  id SERIAL PRIMARY KEY,
  title text NOT NULL,
  content text NOT NULL,
  type_name text NOT NULL,
  timestamp bigint NOT NULL,
  is_favorite boolean NOT NULL DEFAULT false,
  style_json text NOT NULL,
  user_id uuid REFERENCES auth.users NOT NULL DEFAULT auth.uid()
);

ALTER TABLE public.saved_qrs ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can view own qrs" ON public.saved_qrs FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "Users can insert own qrs" ON public.saved_qrs FOR INSERT WITH CHECK (auth.uid() = user_id);
CREATE POLICY "Users can update own qrs" ON public.saved_qrs FOR UPDATE USING (auth.uid() = user_id);
CREATE POLICY "Users can delete own qrs" ON public.saved_qrs FOR DELETE USING (auth.uid() = user_id);

Database Management

Managing your Supabase database is straightforward. Here are common tasks you might need to perform:

Upgrading User Plans Manually

If you want to upgrade a specific user (e.g., to the lifetime $300 Pro Plan), you can run this SQL command:

UPDATE public.profiles 
SET plan = 'pro' 
WHERE email = 'user@example.com';

Note: If this returns "0 rows affected", it means the user hasn't logged into the app yet. They must log in at least once to create their profile.

In-App Notifications Table

To send global notifications to users, create this table in the Supabase SQL Editor. You can set an expires_at date to automatically hide the notification after a specific duration (e.g., 60 days):

CREATE TABLE IF NOT EXISTS public.app_notifications (
  id SERIAL PRIMARY KEY,
  title text NOT NULL,
  message text NOT NULL,
  is_active boolean DEFAULT true,
  created_at timestamp with time zone DEFAULT timezone('utc'::text, now()),
  expires_at timestamp with time zone -- Set to a future date to expire, or leave NULL for permanent
);

-- Note: Anonymous and authenticated users can view notifications
ALTER TABLE public.app_notifications ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Anyone can view notifications" ON public.app_notifications FOR SELECT USING (true);

-- Insert a test notification valid for 30 days
INSERT INTO public.app_notifications (title, message, is_active, expires_at) 
VALUES (
  'Welcome to NovaQR AI!', 
  'Enjoy unlimited QR code generation with our Pro plan.', 
  true, 
  now() + interval '30 days'
);

Adding New Tables

If you need to extend the app (e.g., adding a user_settings table), go to the Supabase SQL Editor and run:

CREATE TABLE IF NOT EXISTS public.user_settings (
  id SERIAL PRIMARY KEY,
  user_id uuid REFERENCES auth.users NOT NULL,
  dark_mode boolean DEFAULT true,
  notifications_enabled boolean DEFAULT true
);
-- Remember to add RLS policies for any new table!

Updating Data & Upgrading Users

To manually upgrade a user to the "pro" plan (for unlimited QR generations), you can use the Supabase Dashboard Table Editor or run this SQL query:

UPDATE public.profiles
SET plan = 'pro'
WHERE email = 'user@example.com';

To downgrade a user, simply set the plan back to 'free'.

AI Agent Configuration (Live Sync)

The NOVA AI agent dynamically syncs its settings directly from the Supabase database. You can instantly control the agent's behavior, instructions, context motif, and even override its API token without updating the app.

1. Create the Agent Config Table

Run the following SQL in your Supabase SQL Editor to create the configuration table:

CREATE TABLE IF NOT EXISTS public.agent_config (
  id SERIAL PRIMARY KEY,
  prompt text NOT NULL DEFAULT 'You are the NOVA AI Agent. Keep responses helpful and professional.',
  token text,
  motif text
);

-- Insert default configuration row
INSERT INTO public.agent_config (id, prompt, token, motif)
VALUES (1, 'You are the NOVA AI Agent. Keep responses helpful and professional.', NULL, 'Default')
ON CONFLICT (id) DO NOTHING;

-- Allow read access to all users
ALTER TABLE public.agent_config ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Enable read access for all users" ON public.agent_config FOR SELECT USING (true);

2. How it works

The app automatically fetches the agent configuration (Prompt system, custom API token, and Motif) live from this table.

  • prompt: The core System Instruction that defines the agent's persona. The app will automatically inject the user's username, project count, and current pricing plan into this prompt so the AI recognizes them.
  • token: (Optional) If you want to use a different Gemini API token on the fly, paste it here. If left NULL, the app falls back to the default `GEMINI_API_KEY` in the `.env` file.
  • motif: Any contextual motif or theme you want the AI to adhere to (e.g. "Formal", "Pirate", "Cyberpunk").

By modifying the row in your Supabase dashboard, all active users will instantly communicate with the newly configured AI.

Authentication

NovaQR supports Email/Password and Google Sign-In via Supabase Auth.

Google Sign-In Setup

  1. Go to the Google Cloud Console.
  2. Create an OAuth 2.0 Client ID for a Web application.
  3. Add the Web Client ID to your .env file under GOOGLE_LOGIN_KEY.
  4. In Supabase Dashboard, go to Authentication > Providers > Google.
  5. Enable Google and paste your Client ID and Secret.

App Configuration

Learn how to change the core identity of the NovaQR application before publishing to Google Play.

1. Changing the App Name

The name displayed on the user's home screen is controlled by the Android resources string file. To change the App Name:

  1. Open app/src/main/res/values/strings.xml
  2. Locate the app_name string element
  3. Update the value: <string name="app_name">Your New Name</string>

2. Changing the Package Name (Application ID)

The Application ID uniquely identifies your app on the device and in the Google Play Store. To change it:

  1. Open app/build.gradle.kts
  2. Locate applicationId = "com.payfopus.novaqr.app" inside the defaultConfig block
  3. Change it to your unique domain identifier if needed, e.g., applicationId = "com.payfopus.novaqr.app"

3. Changing the App Icon

The launcher icons are located in the app/src/main/res/mipmap-* folders and the adaptive icon configurations in app/src/main/res/mipmap-anydpi-v26.

  1. To easily change the app icon, use Android Studio's Image Asset Studio.
  2. Alternatively, manually replace the ic_launcher_foreground.xml and ic_launcher_background.xml files inside app/src/main/res/drawable.

Pricing Plans

NovaQR uses a "Free vs Pro" freemium model. By default, users are assigned the "free" plan and are limited to 5 QR code generations.

Modifying Plan Limits

The limitations are enforced in the helper logic before allowing QR generation. To adjust these limits:

  1. Open app/src/main/java/com/example/util/PlanLimits.kt
  2. Locate the logic checking the generation limit. You can change the limit from 5 to your desired number of free generations.

Assigning Pro Status

Users' plans are read from the profiles table in Supabase. You can manually upgrade users from the Supabase SQL editor or Table editor, or set up a webhook via a payment provider (like RevenueCat or Stripe) to automatically update the plan column to pro upon purchase.

Live Chat Portal

NovaQR integrates with Tawk.to to provide live chat support directly within the application.

Setting up Tawk.to

  1. Sign up for a free account at Tawk.to.
  2. Create a property for your app.
  3. Retrieve your Property ID and Widget ID from the Tawk.to dashboard (under Administration > Chat Widget).
  4. Update your .env file with these values:
TAWK_PROPERTY_ID=your-property-id
TAWK_WIDGET_ID=your-widget-id

The app will automatically read these variables from the `.env` file and render the chat widget in the Support screen!

Modifying & Customizing

The UI is built entirely using Kotlin and Jetpack Compose. Follow these guidelines to modify the app's visual identity.

Themes and Colors

Colors and typography are managed centrally in app/src/main/java/com/example/ui/theme/Color.kt and Theme.kt.

val SleekPrimary = Color(0xFF6366F1)
val SleekBackground = Color(0xFF0F172A)
val SleekSurface = Color(0xFF1E293B)

QR Code Engine

QR Code generation logic is located in com.example.util.QrGenerator.kt. It leverages ZXing (Zebra Crossing) for core generation and custom Canvas drawing for styles (dots, rounded corners, custom eyes).

Troubleshooting

RLS Policy Errors

If you encounter issues saving QRs or viewing profiles, ensure that Row Level Security is enabled and the user_id column exists on the saved_qrs table.

Google Sign In Failing

Verify that your Web Client ID matches both the .env file and your Supabase Provider settings. Do not use an Android Client ID for Supabase Google Auth; it requires the Web Client ID.
