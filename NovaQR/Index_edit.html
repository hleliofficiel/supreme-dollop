Local Installation & Build

Follow these steps to compile and package NovaQR locally using Android Studio or the Command Line Interface.

Build Environment Requirements

  • Android Studio: Koala (2024.1.1) or newer recommended
  • JDK: Java Development Kit 17+
  • Android SDK: SDK Platform 36 (Minimum SDK 24 / Android 7.0)
  • Gradle: Gradle 8.x with Kotlin DSL (.gradle.kts)

Step-by-Step Compilation

  1. Clone the repository or extract the source code archive.
  2. In the project root, create a file named .env (you can base it on .env.example).
  3. Populate your Supabase URL, Anon Key, and Gemini API Key in the .env file.
  4. Open the project in Android Studio and allow Gradle to complete dependency sync.
  5. Build the debug APK using terminal command:
./gradlew assembleDebug

The compiled APK will be generated at app/build/outputs/apk/debug/app-debug.apk.

Google Authentication

NovaQR provides dual-mode Google Authentication: on-device native Google CredentialManager (direct ID Token exchange without browser tabs) and Browser-based OAuth 2.0 with custom deep links. Follow this guide to configure authentication.

Understanding Error 1: Redirect to http://localhost:3000/?error (ERR_CONNECTION_REFUSED)

If Google OAuth redirects to http://localhost:3000/?error in mobile Chrome, this indicates that Supabase Auth rejected the requested redirect_to URI because it was not listed in Supabase's allowed Redirect URLs whitelist. When unwhitelisted, Supabase falls back to its default Site URL (http://localhost:3000), which fails on mobile devices.

Fix: Log into Supabase Dashboard > Authentication > URL Configuration. In Redirect URLs, add:
com.example.novaqr://callback
novaqr://callback

Understanding Error 2: Error 403: org_internal

This error occurs when your Google Cloud Console OAuth Consent Screen is set to Internal instead of External, blocking non-workspace Google accounts.

Fix: Go to Google Cloud Console > APIs & Services > OAuth consent screen, and change User Type to External.

1. Step-by-Step Fix for Error 403 org_internal

  1. Log into the Google Cloud Console.
  2. Select your project corresponding to the Web Client ID used in Supabase.
  3. Navigate to APIs & Services > OAuth consent screen.
  4. Look at the User Type section. If it shows Internal, click EDIT APP or CHANGE USER TYPE.
  5. Select External and click SAVE.
  6. Fill in mandatory fields (App name: NovaQR, User support email, Developer contact email).
  7. In the Scopes section, ensure the following scopes are added:
    • .../auth/userinfo.email
    • .../auth/userinfo.profile
    • openid
  8. Under Test Users, click PUBLISH APP (or add your email address under test users).

2. Native Google CredentialManager vs Browser OAuth

NovaQR automatically attempts native CredentialManager sign-in first. If valid keys are provided in .env, Android displays Google's native account sheet directly inside the app, retrieves a signed ID token, and authenticates with Supabase without opening a browser or performing web redirects.

If CredentialManager is unavailable or canceled, the app falls back to browser OAuth using com.example.novaqr://callback deep link.

3. Configuring Keys in .env

You can configure Google login parameters dynamically via the root .env file without hardcoding credentials in Kotlin source code:

# Google OAuth Web Client ID (from Google Cloud Console)
GOOGLE_LOGIN_KEY=YOUR_GOOGLE_WEB_CLIENT_ID.apps.googleusercontent.com

# Custom Deep Link Redirect URI
GOOGLE_CUSTOM_REDIRECT_URL=com.example.app://callback

Supabase Database Setup

NovaQR utilizes Supabase PostgreSQL for persistent user data, saved QR codes, in-app notifications, and dynamic agent configuration. Execute the SQL scripts below in your Supabase SQL Editor.

1. User Profiles Table

CREATE TABLE IF NOT EXISTS public.profiles (
  id uuid REFERENCES auth.users ON DELETE CASCADE PRIMARY KEY,
  email text,
  full_name text,
  plan text DEFAULT 'free',
  avatar_base64 text,
  created_at timestamp with time zone DEFAULT timezone('utc'::text, now())
);

ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can view own profile" ON public.profiles FOR SELECT USING (auth.uid() = id);
CREATE POLICY "Users can insert own profile" ON public.profiles FOR INSERT WITH CHECK (auth.uid() = id);
CREATE POLICY "Users can update own profile" ON public.profiles FOR UPDATE USING (auth.uid() = id);

2. Saved QRs Table

CREATE TABLE IF NOT EXISTS public.saved_qrs (
  id SERIAL PRIMARY KEY,
  title text NOT NULL,
  content text NOT NULL,
  type_name text NOT NULL,
  timestamp bigint NOT NULL,
  is_favorite boolean NOT NULL DEFAULT false,
  style_json text NOT NULL,
  user_id uuid REFERENCES auth.users NOT NULL DEFAULT auth.uid()
);

ALTER TABLE public.saved_qrs ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can view own qrs" ON public.saved_qrs FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "Users can insert own qrs" ON public.saved_qrs FOR INSERT WITH CHECK (auth.uid() = user_id);
CREATE POLICY "Users can update own qrs" ON public.saved_qrs FOR UPDATE USING (auth.uid() = user_id);
CREATE POLICY "Users can delete own qrs" ON public.saved_qrs FOR DELETE USING (auth.uid() = user_id);

3. Global In-App Notifications

CREATE TABLE IF NOT EXISTS public.app_notifications (
  id SERIAL PRIMARY KEY,
  title text NOT NULL,
  message text NOT NULL,
  is_active boolean DEFAULT true,
  created_at timestamp with time zone DEFAULT timezone('utc'::text, now()),
  expires_at timestamp with time zone
);

ALTER TABLE public.app_notifications ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Anyone can view notifications" ON public.app_notifications FOR SELECT USING (true);

External Database Setup

If you prefer to host your own PostgreSQL instance, AWS RDS, GCP Cloud SQL, or custom REST backend instead of managed Supabase, NovaQR provides flexible database connection methods.

Option 1: Connecting External PostgreSQL to Supabase

Supabase allows connecting external PostgreSQL databases via connection pooling (pgBouncer) or direct connection string in your Supabase Dashboard under Database Settings > Connection Strings.

Option 2: Self-Hosting Supabase Backend

You can deploy self-hosted Supabase using Docker Compose on any VPS (DigitalOcean, Hetzner, AWS EC2):

git clone --depth 1 https://github.com/supabase/supabase
cd supabase/docker
cp .env.example .env
docker compose up -d

Update your .env file with your custom domain URL:

SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY

Option 3: Custom REST API Endpoint Adapter

To point NovaQR to a custom Node.js, Python, or Go REST backend, update the base URL in app/src/main/java/com/example/data/SupabaseClient.kt.

Proxy, Security Policies & Agent Context Permissions

This technical guide outlines how developers can manage backend proxy gateways, configure strict security policies to prevent data leaks, control AI models and live tools (Gemini, OpenRouter, Tawk.to, System Prompts), and safely grant or restrict agent context access to user personal data.

1. Proxy Architecture & Custom Middleware Gateway

By default, NovaQR communicates directly with secure HTTPS endpoints defined in .env (Supabase REST/Realtime, Google Gemini REST API, and Tawk.to Embedded Live Support). If you want to deploy an intermediary API proxy or serverless gateway (such as a Node.js Express proxy in a /proxy directory or Supabase Edge Functions):

// Example Proxy Middleware Structure (/proxy/index.js)
const express = require('express');
const rateLimit = require('express-rate-limit');
const app = express();

// Rate Limiting to Prevent API Abuse
const apiLimiter = rateLimit({
    windowMs: 15 * 60 * 1000, // 15 minutes
    max: 100 // Limit each IP to 100 requests per window
});

app.use('/v1/', apiLimiter);

// Endpoint Proxying & Sanitize User Headers
app.post('/v1/ai/chat', async (req, res) => {
    const { message, user_token } = req.body;
    // Strip private user tokens before forwarding to third-party AI models if required
    // Forward request to Gemini or OpenRouter
});

2. Service Control Hub (AI Models, System Prompts & Live Chat)

Developers can control every active service dynamically without modifying application source code:

  • Gemini AI Model Switcher: Set GEMINI_MODEL=gemini-2.5-flash or gemini-1.5-pro in .env or update agent_config table in Supabase.
  • OpenRouter Fallback Routes: Set OPENROUTER_MODEL and OPENROUTER_FALLBACK_MODEL in .env for automatic multi-provider model routing.
  • System Prompt Override: Modify GEMINI_SYSTEM_PROMPT in .env or update the prompt column in Supabase public.agent_config table (id = 1).
  • Tawk.to Live Chat Control: Configure TAWK_PROPERTY_ID and TAWK_WIDGET_ID in .env. To prevent visitor identity spoofing, enable Tawk.to Identity Verification Hash in Tawk.to Admin settings.
  • Database RLS Policy Protection: Leave Supabase Row-Level Security (RLS) enabled on all tables to prevent cross-account data leaks. Users can only query rows where auth.uid() = user_id.

3. Agent Context Permissions & User Data Privacy

When communicating with NOVA, the agent receives system context parameters so it can assist the logged-in user effectively. Developers can control what information the agent is allowed to access:

Permission Level Context Transmitted to AI Recommended Use Case
Full Personalization (Default) Display Name, Account Email, Plan Status (Free/Pro), Saved QR counts Standard live assistant experience with personalized greetings and status aware responses.
Anonymized Context User ID hash, Plan Status only (Display Name & Email omitted) Privacy-focused environments where personal identifiers must be stripped before sending to LLM APIs.
Isolated / Mock Mode Zero user context (Generic system prompt only) Public demo builds, offline sandbox testing, or guest preview modes.

4. Mock Response & Sandbox Development Policy

For developers creating offline test environments or mocking API integrations:

  • To enforce Mock Mode without external network requests, comment out SUPABASE_URL or GEMINI_API_KEY in .env (prefix line with #).
  • When keys are commented out or invalid, NovaQR gracefully falls back to local in-memory state engines and mock storage without throwing network crashes.

Frequently Asked Questions (FAQ)

Find instant, self-service answers to common installation, authentication, database, and configuration questions.

Q: Why does Google OAuth redirect to http://localhost:3000/?error with ERR_CONNECTION_REFUSED?

Root Cause: Supabase Auth rejected the deep link redirect URI because com.example.novaqr://callback was missing from Supabase's allowed Redirect URLs. When unwhitelisted, Supabase falls back to its default Site URL (http://localhost:3000), causing Chrome to display ERR_CONNECTION_REFUSED.

Actionable Fix: Log into Supabase Dashboard > Authentication > URL Configuration. In the Redirect URLs field, add:
com.example.novaqr://callback
novaqr://callback
Click Save and test Google login again.

Q: How do I fix Error 403: org_internal when signing in with Google?

Root Cause: Your Google Cloud Console OAuth Consent Screen is set to "Internal" mode, restricting login exclusively to users within your Google Workspace organization.

Actionable Fix: Go to Google Cloud Console > APIs & Services > OAuth consent screen. Click CHANGE USER TYPE or EDIT APP, select External, save required developer emails, and click PUBLISH APP under Test Users.

Q: Why does native Google CredentialManager fail or throw developer error code 10?

Root Cause: The OAuth 2.0 Web Client ID in .env (GOOGLE_LOGIN_KEY) does not match your Google Cloud Web Client ID, or the app's SHA-1 signing fingerprint is missing from Google Cloud Console.

Actionable Fix: Ensure GOOGLE_LOGIN_KEY=YOUR_GOOGLE_WEB_CLIENT_ID.apps.googleusercontent.com
